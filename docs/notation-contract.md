# 표기 규약 (mdedit ↔ /scr 세트 SoT)

mdedit과 /scr은 한 세트다. /scr이 발언 대본을 생성하고, mdedit이 미팅 중 텔레프롬프터로 띄운다. 이 문서가 둘이 공유하는 표기 규약의 단일 기준이다. mdedit의 파서(`frontend/src/lib/scr-plugins.ts`)와 /scr 스킬(`~/.claude/skills/scr/SKILL.md`)이 모두 이 규약을 따른다.

## 한눈에

| 쓰는 법 | 의미 | mdedit 렌더 |
|---|---|---|
| `**텍스트**` | 강조(실제로 말할 핵심) | 굵게 + 또렷한 색 |
| `==텍스트==` | 흘긋 봐도 잡을 형광 | 단색 형광 배경 |
| `**소개**` 등 단독 굵은 단어 | 콘텐츠 타입 라벨 | 타입군별 색 칩 |
| `(소개)` 줄머리 (구형) | 콘텐츠 타입 라벨 | 타입군별 색 칩 |
| 한국어 아래 `*English*` 단독 단락 | 영어 백업 | 흐린 작은 이탤릭 |
| `상대가 …하면:` / `만약 …하면:` | 분기 cue | 좌측 테두리 + 틴트 블록 |

## 콘텐츠 타입 라벨

표준 라벨과 색 타입군. mdedit은 curated set만 칩으로 바꾼다. 일반 문서의 임의 괄호·굵은 단어는 건드리지 않는다.

| 타입군 | 색 계열 | 라벨 |
|---|---|---|
| intro | teal | 소개, 오프닝 |
| frame | cyan/blue | 프레임, 어젠다(구형), 기준, 레버리지, 제안 |
| ask | indigo | 묻는다, 질문(구형), 확인, 후속(구형), 답에 따라 |
| answer | purple | 되물으면, 답변(구형), 입장 |
| context | gray | 설명, 배경(구형), 정리, 레퍼런스 |
| close | green | 마무리 |
| caution | amber | 우려, 리스크, 카드 |

현행 /scr 표준 8종은 소개·프레임·설명·묻는다·답에 따라·되물으면·입장·마무리다. 구형 스크립트의 어젠다·배경·질문·후속·답변도 같은 색으로 받는다.

라벨은 두 형식을 모두 지원한다.

- 현행: 단독 굵은 단어 줄. `**소개**` 한 줄, 그 아래 발언.
- 구형: 줄머리 괄호. `(소개) 발언`.

## 하이라이트

`==핵심 문구==`. 섹션마다 반드시 꽂아야 할 문구나 눌러야 할 카드 한둘에만 쓴다. 남발하면 형광이 흔해져 효과가 죽는다.

## 한·영 백업

한국어 단락을 쓰고 빈 줄 하나 띄운 뒤, 영어를 단독 단락으로 이탤릭(`*...*`) 처리한다. mdedit은 "단락 전체가 이탤릭 하나"인 경우만 영어 백업으로 보고 흐리게 렌더한다. 문장 중간의 일반 이탤릭 강조는 건드리지 않는다.

## 분기 블록

`**답에 따라**` 라벨 아래에 갈래별 불릿을 깐다. 각 불릿은 `상대가 X라고 하면: 발언` 형식. mdedit은 "만약" 또는 "상대가"로 시작하고 조건 cue(`…하면:`, `…한다면:`, 콜론 종결)를 가진 줄만 분기 블록으로 렌더한다. "만약에도 …" 같은 일반 문장은 잡지 않는다.

## 오감지 방지 원칙

mdedit 파서는 보수적으로 동작한다. 라벨은 curated set + 줄머리에서만, 분기는 명시 cue에서만, 영어 백업은 이탤릭 단독 단락에서만 변환한다. 일반 4000여 개 문서가 오작동으로 깨지지 않게 하는 것이 우선이다.

## 읽기 모드

mdedit에서 `Cmd/Ctrl+.`로 읽기/발표 모드를 켠다. 사이드바와 패널을 숨기고 본문을 크게(20px, 넓은 행간) 띄운다. 종료는 `Esc` 또는 우상단 툴바의 종료 버튼. 파일이 열렸을 때만 적용되며 상태는 브라우저에 기억된다.

읽기 모드 안에서 쓸 수 있는 단축키와 툴바.

- 글자 크기: `+`/`-`로 키우고 줄이며 `0`으로 초기화. 툴바의 `A−`/`A+` 버튼도 같다. 80~180% 범위로 기억된다.
- beat 점프: `j`(다음)/`k`(이전)로 라벨·분기 블록 사이를 발언 단위로 건너뛴다.
- 인쇄/PDF: 툴바의 "인쇄" 버튼. 사이드바·패널을 빼고 본문만 출력하며 형광·칩·분기 색을 유지한다. 미팅 종이 백업용.
- 스크롤 위치는 파일별로 기억된다. 돌아오면 보던 지점으로 복원되고, 새 파일은 최상단에서 시작한다.
