# v0.5.0 개선안 스펙

> Layer 1 산출물. 각 항목은 feature 브랜치 1개에 대응한다.

## 1. 패널 독립 스크롤 (`feat/independent-scroll`)

**문제**: `.app { min-height: 100vh }` 구조라 문서가 길어지면 body 전체가 스크롤되어 좌측 리스트가 화면 밖으로 사라진다.

**변경**:
- `.app`을 `height: 100dvh; overflow: hidden` 고정 그리드로 전환
- `.sidebar`는 자체 `overflow-y: auto` 유지 (이미 있음)
- `.main`을 스크롤 컨테이너(`overflow-y: auto`)로 감싸고, 문서 전환 시 스크롤 위치 0으로 리셋
- Reader의 `scrollIntoView` 라인 점프는 컨테이너 내부 스크롤로 동작하므로 영향 없음 — 단 검증 필수

**수용 기준**:
- [ ] 긴 문서를 끝까지 스크롤해도 좌측 리스트가 그대로 보인다
- [ ] 검색 hit 클릭 시 해당 라인으로 점프가 여전히 동작한다
- [ ] 문서 전환 시 우측 패널이 맨 위에서 시작한다
- [ ] outline 사이드바(P3)와 모바일(1컬럼) 레이아웃이 깨지지 않는다

## 2. 검색 랭킹 점수 (`feat/search-ranking`)

**문제**: 백엔드는 줄 단위 bm25(`ORDER BY rank`)만 사용. 짧은 스쳐가는 언급이 본문 문서보다 위에 노출됨. 현재 프론트(FlatList)에서 제목>파일명>경로 tier 후처리로 임시 보정 중 — 점수 모델이 아니라서 동률 처리·최근성 반영 불가.

**변경** (랭킹을 백엔드로 승격):
- `index.py search()`에서 hit별 점수 계산:
  - `score = bm25_rank + title_boost + name_boost + path_boost + recency_boost`
  - 제목(첫 H1 또는 frontmatter title) 매치: 강한 부스트
  - 파일명 매치: 중간 부스트
  - 경로 매치: 약한 부스트
  - 최근 수정(7일/30일 단계): 약한 부스트 (mtime은 files 테이블에 있음)
- 파일 단위 대표 점수로 파일 그룹 정렬, 파일 내 hit은 라인 순
- `files` 테이블에 `title` 컬럼 추가(인덱싱 시 추출) — 프론트의 title 조회 의존 제거
- FlatList의 tier 후처리 제거 (백엔드 순서 신뢰)

**수용 기준**:
- [ ] 제목에 검색어가 있는 문서가 본문 한 줄 언급 문서보다 위
- [ ] 동일 tier면 bm25 순서 유지
- [ ] 검색 응답 스키마 하위 호환 (기존 필드 유지)
- [ ] 백엔드 테스트로 랭킹 순서 검증 (기존 83개 + 신규)

## 3. 별표 고정 (`feat/starred`)

**변경**:
- SQLite `starred(path TEXT PRIMARY KEY, starred_at INTEGER)` 테이블
- API: `GET /api/starred`, `PUT /api/starred/{path}`, `DELETE /api/starred/{path}`
- FlatList: 항목 hover 시 ☆ 버튼 → 클릭 시 ★. 별표 파일은 리스트 최상단 "고정" 섹션에 starred_at 역순으로 표시
- 파일이 삭제/이동되면 인덱싱 시 starred에서 정리

**수용 기준**:
- [ ] 별표 토글이 새로고침 후에도 유지된다 (DB 영속)
- [ ] 별표 파일이 리스트 최상단 섹션에 고정된다
- [ ] 필터/검색 중에는 고정 섹션이 검색 결과를 가리지 않는다 (검색 모드에서는 일반 랭킹)
- [ ] 존재하지 않는 경로 star 시 404

## 4. 네이티브 앱 포장 + .md 연결 (`feat/desktop-app`)

**문제**: localhost를 수동으로 띄워 브라우저로 접속하는 흐름이 번거로움.

**변경**:
- `desktop/` 디렉터리 신설: pywebview 진입점 (`uvicorn`을 스레드로 띄우고 네이티브 WKWebView 창 오픈, 포트 충돌 시 기존 인스턴스 재사용)
- PyInstaller spec으로 `mdedit.app` 빌드 (프론트 빌드 산출물 포함)
- Info.plist에 `.md` / `net.daringfireball.markdown` UTI 핸들러 등록
- Finder에서 .md 더블클릭 → 앱이 파일 절대경로를 받아 config roots와 대조해 가상 경로로 변환 → 해당 문서 오픈 (roots 밖 파일이면 안내 메시지)
- 빌드 스크립트 `desktop/build.sh` → `.dmg` 생성 (서명 없음, 개인용)

**수용 기준**:
- [ ] Dock에서 더블클릭으로 앱 실행 (터미널 불필요)
- [ ] .md 더블클릭 시 mdedit 창에서 해당 문서가 열린다 (앱 미실행/실행 중 모두)
- [ ] 앱 종료 시 백엔드 프로세스도 종료된다
- [ ] 기존 브라우저 접속(`localhost:8787`)도 계속 동작 (회귀 없음)
