# v0.7.0 스펙 — 글로벌 .md 핸들러 완성

> v0.6.0에서 .md 전역 기본 핸들러로 등록했지만 vault(roots) 밖 파일은 열리지 않는다.
> 이번 사이클로 "아무 .md나 더블클릭하면 열린다"를 완성한다.

## 1. vault 밖 .md 임시 열기 (`feat/external-open`)

**문제**: `POST /api/open`이 roots 밖 절대경로에 404를 반환 → Finder에서 vault 밖 .md 더블클릭 시 아무 일도 안 일어남.

**설계** — `ext://` 가상 스킴 + 인메모리 등록제:
- `/api/open`: roots 매칭 실패 시, 실존하는 `.md` 파일이면 인메모리 레지스트리에 절대경로 등록 후 `ext://<abs_path>` 가상 경로를 pending으로 전달 (404 제거)
- `/api/file`: `ext://` 경로는 **레지스트리에 등록된 경로만** 읽기 허용 (미등록 404 — 임의 파일 노출 방지). `.md` 확장자 + 실존 확인
- 인덱스·검색·백링크·그래프 대상 아님 (표시 전용, 재시작 시 휘발)
- Reader 헤더에 "vault 밖 문서" 배지 노출 (frontmatter 카드 위치에 경로 안내)
- 데스크톱 흐름은 변경 없음 (`_post_open` 그대로 — 백엔드가 판단)

**수용 기준**:
- [ ] roots 밖 .md 더블클릭 → mdedit 창에서 열림
- [ ] 등록 안 된 `ext://` 경로 직접 요청 시 404 (보안)
- [ ] `.md` 아닌 파일, 존재하지 않는 파일은 422/404
- [ ] 기존 roots 내 열기 흐름 회귀 없음 (기존 14개 open 테스트 통과)

## 2. 업데이트 체크 (`feat/update-check`)

**설계**:
- `GET /api/update-check`: GitHub `releases/latest`를 조회(타임아웃 3s, 1시간 캐시)해 현재 버전과 semver 비교 → `{current, latest, update_available, url}`. 네트워크 실패 시 `update_available: false` (조용히)
- 프론트: 사이드바 하단에 버전 표기. 업데이트 있으면 `v0.7.0 → v0.8.0 ↗` 형태의 작은 배지 (클릭 → Release 페이지 새 탭). 무광고 톤 — 액센트 컬러 텍스트만
- 버전 소스: FastAPI `app.version` 단일 참조

**수용 기준**:
- [ ] 최신이면 배지 없음, 구버전이면 배지 노출
- [ ] 오프라인에서 에러 없이 무표시
- [ ] semver 비교 유닛 테스트 (0.9.0 < 0.10.0 케이스 포함)
